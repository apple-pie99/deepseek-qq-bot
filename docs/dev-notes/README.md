# dev-notes：动手之前先量一遍

这四篇不是教程，是**踩坑前的勘察记录**。写它们的原因是：这类项目 90% 的失败不是"不会写代码"，
而是"配置写在了没人看的地方"——`provider` 和 `provider_sources` 是两个字段、
人设不在配置文件里而在 SQLite 里、`prompt_prefix` 拼的是用户消息。

## 怎么读

- 想知道"为什么这样配"→ 01 / 02。
- 想知道"为什么温度不能给 1.3"→ 03，里面有 20 条探针的崩坏原文。
- 换 AstrBot 版本后配置项报错 → 先翻 01，再去对源码。

## 一个约定

这些记录都带日期和版本号。上游改动频繁，**结论会过期**。
用的时候先看文首的记录时间；如果和你的版本差得远，以源码为准，并欢迎提 PR 修正。

## 改脚本前必读：BOM

`.ps1` **必须存成 UTF-8 with BOM**。Windows PowerShell 5.1 对无 BOM 的 UTF-8 按 ANSI（GBK）解码，
中文注释会变成乱码，乱码里的字节还可能吃掉引号，直接报「缺少右 `}`」这类莫名其妙的语法错。
`.editorconfig` 已经为 `*.ps1` 声明了 `charset = utf-8-bom`，用 VS Code 编辑会自动保持；
用别的编辑器改完，记得确认 BOM 还在。

`.bat` 相反，**不能带 BOM**（cmd 会把 BOM 当命令的一部分）。
