# 常见问题与排查

按**现象**查，不按理论查。每条都是实际撞过并修好的。

先记住两件事：

- 日志在 `app\AstrBot_<版本>_windows_amd64_portable\data\logs\`（`astrbot.log` 最新、最全）。
- 说不清就先跑 `诊断\收集日志.bat`，产出的 zip 里 Key 和 token 已打码，可以直接贴。

---

## 群里它没反应

按这个顺序查，**四步走完再谈其他**：

| 步 | 检查 | 怎么确认 |
|---|---|---|
| 1 | NapCat 是否已登录小号 | NapCat 页面/日志里有账号在线状态；QQ 手机上显示"电脑端已登录" |
| 2 | 反向地址是否是 `ws://127.0.0.1:6199/ws` | 少 `/ws`、写成 `wss://`、写成 `127.0.0.1:6199` 都不行 |
| 3 | Token 是否与向导打印的一致 | 一个字符都不能差。改了配置要**重载/重启** NapCat 才生效 |
| 4 | AstrBot 是否在跑 | 浏览器打开 `http://127.0.0.1:6185`，能打开说明进程活着 |

四步都对还不通，看 AstrBot 日志里有没有 OneBot 客户端的连接记录：

- **有连接、没消息** → 群消息被 AstrBot 的唤醒规则挡了（见下一条）。
- **没连接** → 网络层没通，检查 NapCat 的「网络配置」是否**启用**、端口有没有被别的程序占用。

### 手打的 @ 不算唤醒

在 QQ 输入框里用键盘打出来的 `@名字` 只是普通文本，AstrBot 收不到 at 段。
必须用 QQ 的 @ 选择器点到机器人，日志里才会出现 `[At:机器人QQ号]`。

另外，以 `/` 开头的消息通常也会唤醒它（取决于 `wake_prefix` 配置）。

## 报「未找到任何可用的对话模型」

**根因：`provider_sources` 和 `provider` 是两个东西。**

- `provider_sources`：这是"哪家 API + Key"（端点、密钥）。
- `provider`：这是"具体用哪个模型"（模型名、引用了哪个 source）。

只写前者时，AstrBot 启动时遍历的是后者（`provider`），列表为空 → 一个模型都不加载 → 所有消息都失败。

向导已经同时写了两者。如果你手动改过配置、把这个条目删了，补回来即可：

```json
{
  "id": "deepseek-chat",
  "type": "openai_chat_completion",
  "provider_type": "chat_completion",
  "provider_source_id": "deepseek",
  "model": "deepseek-chat",
  "enable": true
}
```

⚠️ 这个条目里**不要**再写 `key` 或 `api_base`。合并规则是 `{**source, **provider}`，provider 优先，写空值会把 source 里的真 Key 覆盖掉。

## NapCat 注入失败 / 起来了但 QQ 没反应

这是 NapCat 管理器的路径拼接 bug：它把 `D:\QQ` 和 `Versions\9.x\...` 拼成了 `D:\QQVersions\...`（少一个反斜杠），导致注入脚本找不到。

典型表现：日志里有 `loadNapCat.js` 相关报错，QQ 进程起来了但没有任何 OneBot 连接。

修法（任选）：

1. 建目录联接，把两段接上：

   ```bat
   mklink /J "D:\QQVersions" "D:\QQ\versions"
   ```

2. 或者手动把管理器的注入脚本复制到 QQ 的 app 目录：

   ```
   C:\ProgramData\NapCatQQ Desktop\components\NapCatQQ\loadNapCat.js
   → D:\QQ\versions\<你的版本号>\resources\app\
   ```

版本号目录写你机器上实际的那个。做完重启 QQ 和 NapCat。

## 启动卡住、不下发 6185 端口

`data\dist` 缺失时，AstrBot 会尝试**从网上下载**管理面板，国内网络下会长时间卡住。

修法：把便携包自带的编译产物复制一份：

```powershell
cd .\app\AstrBot_4.29.1_windows_amd64_portable
Copy-Item -Recurse -Force .\webui\* .\data\dist\
```

## 它说话开始"胡话"、夹英文、人称错乱

温度太高。DeepSeek 官方建议通用对话用 1.3，但**人设场景下 1.3 会崩**。

实测（同一套 20 条探针、同一条链路、同一个示例人设）：

| 温度 | 崩坏 | 典型症状 |
|---|---|---|
| 1.3 | 4 / 20 | 「写字的活，Turbo 只会写训练笔记」（夹英文）、「让涡轮重跑给我看」（人称错乱）、整段废句 |
| 1.0 | 0 / 20 | 全部通顺、在角色内 |

改法：`data\cmd_config.json` 里 `provider_sources` 中 DeepSeek 那条的 `custom_extra_body.temperature` 改成 `1.0`，或直接改 `preset\astrbot\provider_deepseek.json` 后重跑向导。

## QQ 更新之后突然不能用了

QQ 的自动更新会替换 `resources\app\` 下的注入点，NapCat 的 `loadNapCat.js` 被冲掉，注入失败。

- 临时：重装一次 NapCat（或重新复制注入脚本，见上一节）。
- 长期：关掉 QQ 自动更新（设置里关自动更新；必要时把更新包改名成 `.disabled`）。

---

## 双击 bat 窗口一闪就没了

说明脚本抛异常后立即退出。临时看错误：

```powershell
# 在项目根目录打开 PowerShell，手动跑，错误会留在窗口里
powershell -NoProfile -ExecutionPolicy Bypass -File .\lib\wizard.ps1 -PackRoot "."
```

常见原因：没有 `app\` 目录（没跑第 2 步）、没生成 `data\cmd_config.json`（没跑第 3 步）、PowerShell 执行策略被组策略锁死。

## 下载依赖卡住 / 一直 0%

- 先确认代理开着，且**混合端口**（不是 HTTP 端口）是 7890。
- 端口不对：编辑 `installer\下载依赖.bat`，最后一行加 `-ProxyUrl "http://127.0.0.1:你的端口"`。
- `curl.exe` 缺失：Windows 10 1803 之后自带；太老的系统需要手动装，或升级系统。
- 下到一半失败：脚本会校验字节数并退出，直接重跑即可（已完成的会跳过）。

## API 校验报 401 / 402

| 码 | 含义 | 处理 |
|---|---|---|
| 401 | Key 无效 / 已删除 / 粘错了 | 重新申请，注意别把换行、空格粘进去 |
| 402 | 余额不足 | 去 platform.deepseek.com 充值 |
| 000 | 网络不通 | 开代理；确认 `api.deepseek.com` 可访问 |

## 它说话太像客服

三个原因，按顺序排：

1. **没设人设** —— 默认 persona 就是"乐于助人的助手"。按[人设指南](人设指南.md)写一份。
2. **人设写得太抽象** —— "温柔善良"这种词没有行为约束力，模型只能照着词演，演成谁都像的客服。
3. **人设写错了位置** —— 塞进 `prompt_prefix` 是无效的，那是拼在用户消息上的。必须写到 `personas` 表（向导会自动做）。

跑一遍 `lib\persona_qa.py`，看 20 条探针里有没有命中"作为一个AI""语言模型""抱歉"这类词。

## 回复太慢 / 一次发一大段

| 现象 | 调整 |
|---|---|
| 一次发一大段 | 面板里开启**分段回复**，间隔 1.5–3.5 秒最自然 |
| 回复慢 | 检查是不是走了代理、模型是否 `deepseek-chat`；群聊上下文开到 700 条会显著增加输入 token |
| 偶尔卡 15 分钟 | 超时/重试设置过大（默认可能是 120 秒 × 5 次），改成 60 秒 / 2 次 |
| 打断、抢话 | `active_reply` 概率调低（0.1–0.2） |

这些都在 `http://127.0.0.1:6185` 面板里改，改完不需要重启。

## 配置改坏了怎么回滚

向导每次写配置前都会备份：

```
app\AstrBot_4.29.1_windows_amd64_portable\data\cmd_config.json.bak_20261024_121500
```

把备份改回 `cmd_config.json` 即可。人设在 `data_v4.db` 里，向导不备份数据库——改人设前建议整个 `data\` 目录复制一份。

---

## 怎么彻底备份 / 迁移到另一台机器

需要带走的东西：

```
app\AstrBot_4.29.1_windows_amd64_portable\data\cmd_config.json   配置（含 Key，别外传）
app\AstrBot_4.29.1_windows_amd64_portable\data\data_v4.db        人设、会话
preset\persona\_我的设定.md                                      人设原文
napcat\ 里与登录态相关的目录                                      登录态（可选，通常重扫更简单）
```

依赖（`app\`、`napcat\`）不用带，新机器跑一次 `installer\下载依赖.bat` 即可。

## 端口被占用

```powershell
netstat -ano | findstr ":6185 :6199"
taskkill /PID <上面的PID> /F
```

改端口不是只改一处：`cmd_config.json` 里的 `dashboard.port`、平台条目的 `ws_reverse_port`，以及 NapCat 里的反向地址，三处要一致。
