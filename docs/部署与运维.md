# 部署与运维

## 三种放法

| 方案 | 成本 | 账号风险 | 网络稳定性 | 适合谁 |
|---|---|---|---|---|
| **本机常开**（推荐先做） | 0 | 不变（还是你家的 IP） | 看宽带，校园网会抖 | 大多数人 |
| 家里的小主机 / NAS | 一台低功耗机器 | 低（真实家用 IP） | 好 | 有闲置设备 |
| 云服务器 | 几十元/月起 | **最高** | 最好 | 能接受风控的人 |

### 为什么云上风险最大

1. **风控**：家庭/校园 IP 突然变成机房 IP + 异地登录，新号极易被要求验证或冻结。
2. **云厂商条款**：自动化挂 IM 协议端属于灰色地带，异常流量可能被停机。
3. **内存**：Linux QQ + NapCat 约 1–1.5 GB，AstrBot 约 300–500 MB，**2 GB 机器跑不动**，至少 2C4G。
4. **Linux 上的 NapCat 只能走 Docker**，登录态必须挂 volume，否则每次重启都要重新扫码。

结论：**先本机**。真要上云，按"本机不休眠 → 家里闲置设备 → 云"的顺序试。

## 本机常开：怎么不关机也能跑

### 1. 关掉睡眠

设置 → 系统 → 电源 → 屏幕和睡眠：把"接通电源时进入睡眠"改成**从不**。
笔记本盖上盖子会睡，也一起改掉。

### 2. 开机自启（任务计划程序）

比"启动"文件夹可靠，能设成不需要登录也能跑：

```
任务计划程序 → 创建任务
  常规：勾"不管用户是否登录都要运行"、"使用最高权限运行"
  触发器：登录时（或 启动时）
  操作：启动程序 → 项目：powershell.exe
              参数：-NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File "D:\deepseek-qq-bot\lib\start.ps1" -PackRoot "D:\deepseek-qq-bot"
              起始于：D:\deepseek-qq-bot
```

### 3. 崩了自动拉起

同一任务里勾"如果任务失败，按以下频率重新启动：1 分钟 / 尝试 3 次"。
或者用 [NSSM](https://nssm.cc/) 把 AstrBot 后端注册成服务（更干净，但要自己填命令行）。

> ⚠️ 在 AI 会话里跑的进程（比如本项目调试时用的后台任务）会随会话结束而死。
> 长期运行必须走任务计划或 NSSM，别指望聊天窗口。

## 云上部署（如果你坚持）

思路：两个容器，站在同一条内网里，**只暴露面板端口**。

```yaml
# docker-compose.yml（示意，未随仓库验证）
services:
  astrbot:
    image: soulter/astrbot:latest
    ports:
      - "6185:6185"          # 面板；建议只绑 127.0.0.1 再用 SSH 隧道访问
    volumes:
      - ./astrbot-data:/AstrBot/data
    restart: unless-stopped

  napcat:
    image: mlikiowa/napcat-docker:latest
    environment:
      - NAPCAT_UID=1000
      - NAPCAT_GID=1000
    volumes:
      - ./napcat-config:/app/napcat/config
      - ./napcat-qq:/app/.config/QQ        # 登录态必须持久化，否则每次重启扫码
    ports:
      - "6099:6099"          # NapCat WebUI，同样建议只绑本机
    restart: unless-stopped
```

接线：NapCat 里配反向 WebSocket，地址写 `ws://astrbot:6199/ws`（容器名，不是 127.0.0.1），
Token 与 AstrBot 的 `ws_reverse_token` 一致。

**迁移时需要带走的数据**：

```
astrbot-data/cmd_config.json     配置（含 Key）
astrbot-data/data_v4.db          人设 / 会话
preset/persona/_我的设定.md      人设原文
napcat-qq/                       登录态（不带走就得重新扫码）
```

## 日常运维

### 每天

不用管。出问题它自己在 `data\logs\astrbot.log` 里记。

### 每周

- 看一眼日志尾部有没有反复出现的报错（`grep -i error` 或直接翻）。
- 磁盘：日志和 `data_v4.db` 会慢慢长；`data_v4.db` 超过几百 MB 说明群聊历史攒太多了，
  可以在面板里清会话，或把 `group_message_history` 上限调小。

### 升级 AstrBot

1. 停掉进程（关掉 AstrBot 窗口 / 结束进程）。
2. **先备份** `data\` 整个目录。
3. 用新版便携包覆盖 `app\`，但保留 `data\`（便携版数据在程序目录里，覆盖时别删）。
4. 启动，打开 6185 确认配置还在。

跨大版本升级可能改配置结构，所以第 2 步的备份不能省。

### 升级 NapCat

NapCat 的更新经常是为了跟 QQ 客户端的注入点对齐。QQ 一更新、NapCat 失效时，
直接下最新版覆盖 `napcat\`，配置在 `napcat\config\` 里，会保留。

### 备份什么

```
app\AstrBot_*\data\cmd_config.json     ← 含 API Key，别放公开网盘
app\AstrBot_*\data\data_v4.db
preset\persona\_我的设定.md
```

脚本化：

```powershell
$stamp = Get-Date -Format "yyyyMMdd_HHmmss"
Compress-Archive -Path ".\app\AstrBot_4.29.1_windows_amd64_portable\data\cmd_config.json",
                       ".\app\AstrBot_4.29.1_windows_amd64_portable\data\data_v4.db",
                       ".\preset\persona\_我的设定.md" `
                 -DestinationPath ".\backup_$stamp.zip"
```

### 日志在哪

| 日志 | 位置 |
|---|---|
| AstrBot 主日志 | `app\AstrBot_*\data\logs\astrbot.log` |
| AstrBot 其他 | `app\AstrBot_*\data\logs\` |
| NapCat | `napcat\logs\`；管理器版在 `%LOCALAPPDATA%\com.napcatqq.desktop\logs\` |

`诊断\收集日志.bat` 会把这些打包，并把 Key / token 打码。发给别人前不用再手动改。

## 安全底线

| 事项 | 做法 |
|---|---|
| API Key | 只存在 `data\cmd_config.json` 里，它是明文。不要提交到 git、不要贴群、不要发网盘 |
| 面板 6185 | 默认监听 `0.0.0.0` 且用户名 `astrbot` + 默认密码。**上公网前必须改端口绑定或改密码** |
| NapCat 6099 | 同上，别暴露公网 |
| 诊断 zip | 已经打码，但仍建议自己先打开确认一眼 |
| 本仓库 | `.gitignore` 已排除 `app/`、`napcat/`、`**/data/`、`*.db`、`preset/persona/_我的设定.md` |

## 卸载

删目录即可。没有服务、没有注册表、没有自启项（如果你加过任务计划，记得一起删）。
