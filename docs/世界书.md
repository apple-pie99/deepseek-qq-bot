# 世界书（Worldbook）

人设是"她是谁"，世界书是"她记得什么"。

人设写在 system prompt 里，每轮都在，写多了会冲淡重点、烧 token。世界书按**关键词命中**才注入：
群里聊到"进货"，就把"她今天刚进了一批西瓜"这段塞进上下文；没聊到就不塞。

本项目不包含世界书插件本身，只提供**已经核实过真实字段的格式说明与示例**，
以及可直接改的成品。

## 前置

1. 在 AstrBot 面板的插件市场安装 `astrbot_plugin_worldbook`
   （[Zhalslar/astrbot_plugin_worldbook](https://github.com/Zhalslar/astrbot_plugin_worldbook)，GPL-3.0）。
2. 在插件配置里填「世界书路径」，指向一个 `.yaml` 文件，然后重载插件。
3. 示例文件：[`preset/worldbook/_示例世界书-满记.yaml`](../preset/worldbook/_示例世界书-满记.yaml)
   （与示例人设「林小满」配套，可直接用，也可以拿来当骨架改）。

> 人设没跑顺之前别开世界书。两个变量同时调，出了问题分不清是谁的锅。

## 文件结构

顶层是 **YAML 列表**（每项以 `- ` 开头），不是字典。

```yaml
- template: resident     # 常驻，每次请求都注入
  name: 世界观
  enabled: true
  priority: 10
  content: |
    你生活在一个南方二线城市的社区里，开一家二十来平的杂货店……

- template: default
  name: 称呼规则
  keywords: [你是谁, 你叫什么, 小满]
  content: |
    对方叫 {user_name}……
```

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 条目唯一名；`keywords` 为空时自动当触发词 |
| `content` | ✅ | 命中后注入的设定正文。**早期教程写的 `inject` 是错的**，真字段是 `content` |
| `keywords` | | 关键词或正则，命中才可能激活 |
| `enabled` | | 总开关，`false` 完全不参与判断 |
| `priority` | | 数字越小越靠前、约束越强。通用 30–60，强规则 0–20 |
| `scope` | | 限定用户/群/会话，如 `["admin"]` |
| `cron` | | 定时点名。**不是立即生效**，下一条消息才尝试 |
| `duration` | | 生效秒数，`0` = 永久 |
| `times` | | 单周期最多注入次数，`0` = 不限 |
| `probability` | | 最终生效概率 0–1 |
| `template` | | `default` / `resident`（常驻）/ `chance`（按概率）/ `user` / `group` |

## 可用变量

| 变量 | 替换成 |
|---|---|
| `{user_id}` | 发送者 QQ 号 |
| `{user_name}` | 发送者昵称 |
| `{time}` | 当前时间 |

写错的变量**会原样保留且不报错**，所以务必核对拼写——这种错最难发现。

## 激活逻辑

```
激活资格（满足其一）：keywords 命中 / cron 到点
        ↓
激活门禁（必须全过）：enabled → scope → duration → times → probability（最后判）
```

`probability` 是最后一道闸。想"偶尔提一次"就设 `0.2` 并配 `chance` 模板。

## 三种常用写法

**1. 常驻世界观**——每次请求都带，用来锚定场景，内容要短：

```yaml
- template: resident
  name: 世界观
  priority: 10
  content: |
    你在「满记」杂货店生活，店在社区里，二十来平，后面是隔间。
```

**2. 关键词触发的规则**——只在相关话题出现时注入：

```yaml
- name: 称呼规则
  priority: 40
  keywords: [你是谁, 你叫什么, 小满]
  content: |
    对方叫 {user_name}。熟客直呼其名，刚来的叫「哎」或「你」。
    从不使用「亲爱的用户」「您好」这类说法。
```

**3. 随机彩蛋**——20% 概率：

```yaml
- template: chance
  name: 今天进货
  probability: 0.2
  keywords: [在吗, 忙不忙]
  content: |
    你今天刚进了一批西瓜，正搬得腰疼。
```

## 设计建议

| 建议 | 原因 |
|---|---|
| 常驻条目总长度控制在 300 字内 | 它每轮都在，直接吃上下文和钱 |
| 一条只讲一件事 | 命中时全部注入，长了会盖住人设 |
| `priority` 分层：硬规则 0–20，常识 30–60，彩蛋 60+ | 数字越小越靠前，越靠前越容易被遵守 |
| 别用世界书写"她是 AI 时怎么回答" | 那是人设禁忌栏的活，重复写会打架 |
| 改完必须重载插件 | 配置不是热加载的 |

## 与角色卡（SillyTavern）的关系

理论上一份角色卡（`chara_card_v2` JSON）可以拆成"人设 + 若干世界书条目"。
本项目暂未内置转换器，属于路线图里的一项；现在的做法是手工拆：
描述/性格/场景 → 人设；`character_book.entries` → 世界书条目。
