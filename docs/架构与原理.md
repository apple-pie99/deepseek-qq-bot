# 架构与原理

这份文档回答两个问题：**它到底是怎么跑起来的**，以及**向导到底改了哪几行配置**。
知道这两件事，出问题才有得查。

## 三个进程

| 进程 | 角色 | 对外接口 |
|---|---|---|
| QQ（官方 NT 客户端） | 你的账号本体 | 不对外 |
| NapCat | 把 QQ 的内部协议翻译成 OneBot v11，**作为客户端**连出去 | 反向 WS 客户端 |
| AstrBot | 消息路由、会话、插件、模型调用，**作为服务端**听 6199 | 6185 面板 / 6199 WS |
| DeepSeek API | 生成回复 | HTTPS |

关键点：**AstrBot 是服务端，NapCat 是客户端**。所以叫"反向 WebSocket"——是 QQ 侧主动连到机器人框架，
而不是机器人去连 QQ。这样 AstrBot 不需要暴露公网端口，本机跑就行。

## 一次对话的完整路径

```
1. 群友在群里 @机器人 说一句话
2. QQ 客户端收到，NapCat 注入后拿到 OneBot v11 事件
3. NapCat 通过已建立的反向 WS 推送该事件到 ws://127.0.0.1:6199/ws
      Authorization: Bearer <ws_reverse_token>
4. AstrBot 的 aiocqhttp 适配器解析事件 → 唤醒判定（是否真 @ / wake_prefix）
5. 组装上下文：
      system = personas 表里 persona_id='default' 的 system_prompt
      + datetime_system_prompt（当前时间）
      + identifier（发送者 QQ 号 / 昵称）
      + 群聊历史（group_message_history，上限可调）
      + 本条消息
6. 调 https://api.deepseek.com/v1/chat/completions（key 来自 provider_sources）
7. 拿到回复 → 按分段设置切成几条 → 通过同一个 WS 回发 send_group_msg
8. NapCat 收到动作 → QQ 发出消息
```

第 5 步是"像不像人"的关键：**人设进的是 system，不是用户消息**。

## 向导写了什么

`lib/wizard.ps1` 只做四件事，全部落在 `data\cmd_config.json` 和 `data\data_v4.db`。

### 1. `platform`：加一个 OneBot v11 适配器

```json
{
  "id": "default",
  "type": "aiocqhttp",
  "enable": true,
  "ws_reverse_host": "0.0.0.0",
  "ws_reverse_port": 6199,
  "ws_reverse_token": "astrbot-<随机 24 位>"
}
```

模板：`preset/astrbot/platform_onebot.json`。token 是每次生成的新 GUID 片段，
所以**重跑向导会换 token**，NapCat 那边也要跟着改。

### 2. `provider_sources`：加"哪家 API + Key"

```json
{
  "id": "deepseek",
  "provider": "openai",
  "type": "openai_chat_completion",
  "provider_type": "chat_completion",
  "enable": true,
  "key": ["sk-..."],
  "api_base": "https://api.deepseek.com/v1",
  "timeout": 120,
  "proxy": "",
  "custom_headers": {},
  "custom_extra_body": { "temperature": 1.3 }
}
```

模板：`preset/astrbot/provider_deepseek.json`。

⚠️ `key` 是**数组**，不是字符串。写成一个裸字符串时 AstrBot 认不出来。

### 3. `provider`：加"具体用哪个模型"

```json
{
  "id": "deepseek-chat",
  "type": "openai_chat_completion",
  "provider_type": "chat_completion",
  "provider_source_id": "deepseek",
  "model": "deepseek-chat",
  "enable": true
}
```

模板：`preset/astrbot/provider_model_deepseek.json`。

**这是最容易漏的一步。** 只写 `provider_sources` 时，AstrBot 启动会报
「未找到任何可用的对话模型（提供商）」——因为它遍历的是 `provider` 列表，而那个列表是空的。

合并规则是 `{**source, **provider}`，**provider 优先**。所以这个条目里不要写 `key`、`api_base`，
写了空值会把 source 里的真 Key 覆盖掉。

### 4. `personas` 表：写 system prompt

`lib/set_persona.py` 直接操作 SQLite：

```sql
-- 已存在就更新，不存在就插入（幂等）
UPDATE personas SET system_prompt = ?, updated_at = ? WHERE persona_id = 'default';
```

`persona_id='default'` 是 AstrBot 的系统默认人设 ID，所有会话默认用它。

## 为什么人设不能放 `prompt_prefix`

`provider_settings.prompt_prefix` 看起来像个"系统提示词"，实际不是。AstrBot 的实现是：

```python
req.prompt = prefix.replace("{{prompt}}", req.prompt)
```

它替换的是 **`req.prompt`，也就是用户消息**。后果：

1. AstrBot 自带的 *You are a helpful and friendly assistant.* 依然作为 system prompt 生效，
   模型会同时看到"你是助手"和"你是林小满"，AI 味从缝里漏出来；
2. 每轮都把整段人设当用户输入再发一遍，token 翻倍；
3. 人设越长，越像"用户给我下了一堆指令"，而不是"我就是这个人"。

所以本项目走 `personas` 表。这也是为什么重灌人设必须用脚本或面板，而不是改配置。

## 运行期参数（面板里改，不在仓库里预设）

这些值取决于你的群和你的模型预算，仓库只给建议值：

| 参数 | 建议 | 说明 |
|---|---|---|
| `custom_extra_body.temperature` | **1.0** | 1.3 在该人设下崩 4/20，见 [实测](dev-notes/03-真链路与温度实测.md) |
| `identifier` | `true` | 注入发送者 QQ / 昵称，才能"认得人" |
| `active_reply` | `true`，概率 **0.2** | 主动插话；太高像刷屏机器人 |
| `group_message_history_enable` | `true`，上限 **700** | **只覆盖群聊**，私聊不在内 |
| 分段回复 | `true`，间隔 1.5–3.5 秒 | 一次性发一大段最假 |
| 超时 / 重试 | 60 秒 / 2 次 | 默认可能是 120 秒 × 5 次，断网时会卡十几分钟 |
| `safety_mode` | 视需要 | 开着更安全，代价是偶尔冒客服腔 |

## 数据都在哪

AstrBot 便携版带 `portable.flag`，意思是**数据写在程序自己目录**，不落到 `%APPDATA%`：

```
app\AstrBot_4.29.1_windows_amd64_portable\
├─ AstrBot.exe                        Tauri 外壳
├─ backend\
│  ├─ launch_backend.py               启动器
│  ├─ app\                            AstrBot 源码
│  └─ python\python.exe               ★ 自带 Python 运行时
├─ webui\                             管理面板编译产物
└─ data\
   ├─ cmd_config.json                 全部配置（含 API Key —— 别外传）
   ├─ cmd_config.json.bak_<时间戳>     向导每次写前自动备份
   ├─ data_v4.db                      SQLite：人设、会话、插件数据
   ├─ dist\                           面板运行时副本（缺失会导致启动卡住）
   └─ logs\astrbot.log                出问题先看这个
```

路径规则来自 `astrbot/core/utils/astrbot_path.py`：环境变量 `ASTRBOT_ROOT` 优先，
否则用程序根目录；`data = <root>/data`。

## AstrBot.exe 起不来时：纯后端启动

`AstrBot.exe` 只是个 Tauri 外壳，真身是 Python 后端。外壳挂了可以直接跑后端：

```powershell
$env:ASTRBOT_ROOT = ".\app\AstrBot_4.29.1_windows_amd64_portable"
$env:PYTHONUTF8 = "1"
& ".\app\AstrBot_4.29.1_windows_amd64_portable\backend\python\python.exe" `
  ".\app\AstrBot_4.29.1_windows_amd64_portable\backend\launch_backend.py"
```

前台窗口别关（关了进程就没了）。想常驻就用任务计划程序，见[部署与运维](部署与运维.md)。
